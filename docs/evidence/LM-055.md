## Follow-up — speculative comparison (2026-11-15)

The phone "Compare both" miss came from computing the comparison only after the click. `Explorer.tsx` now computes the comparison in the background once the visible single-framework run is ready (a separate `prefetch-compare` request kind, so it never cancels or replaces what is on screen). The result is keyed by the exact manifest digest, scenario, inputs and sandbox edits. Switching to "Compare both" with the same key uses it immediately. If the background request for those inputs is still running, the switch reuses it instead of starting over. Any change to inputs or edits cancels it.

Local check (production build, Chromium headless, unthrottled, shared busy container; includes Playwright round-trip overhead): click → comparison table rendered took 150 ms when clicking immediately after verification and 93 ms after a 3 s pause, when the prefetched result is used. The throttled phone profile in `scripts/perf-web.mjs` could not complete on this machine because other builds were saturating the CPU, so `docs/evidence/performance-web.json` was **not** regenerated and the 200 ms phone target is still recorded as missed until it is re-measured.
