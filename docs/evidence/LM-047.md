# LM-047 — Validation reports editorial review and publication

Status: Implemented.

Validation job rebuilds from exact stored source bytes and records a report; success stages a release that is privately previewable (`no-store`). Publication requires publisher + recent reauth, refuses stale validations, re-hashes assets, signs and moves the pointer atomically; withdrawal and pointer rollback are audited. Browser E2E covers the lifecycle.

## Verification

`pnpm check` (boundaries, lint, typecheck, unit tests, `packs:check` golden checks, secret scan, SDK consumer smoke), `pnpm build`, the Chromium + axe browser suite against the production build under CSP, and — where database-backed — the PostgreSQL SQL suites and the `authoring` CI job (migrate, server, authoring E2E, backup/restore). Merged only after required checks pass on the exact head via `scripts/verify-pr-merge.mjs`.

Delivered in the combined `lm-complete-integration` PR at the owner's direction ("finish the whole thing at once … as long as all functionalities are integrated"). AI-performed implementation and review only; **no independent human audit is claimed.**


Dependency note: LM-030's executable engine is satisfied by the generic pack runtime; its real-bill content is not. Every acceptance criterion here (no partial release, stale validation refused, missing provenance fails) is tested with the fictional packs.
